| 默认 Excel 导出 | excelize StreamWriter 为主通道，CSV 为备选 |

## 3. 系统库设计（DDL）

系统库采用 **SQLite（默认且推荐，纯 Go 驱动 modernc.org/sqlite，单文件随服务部署）**，MySQL 保留为可选配置。所有表经 GORM 模型定义（方言无关），以下 DDL 为**逻辑结构参考**（MySQL 语法），SQLite 由 AutoMigrate 生成对应物理表。

**SQLite 运行时要求（强制）：**

```go
// 打开参数（modernc 驱动 DSN query 参数）
file:data/report_sys.db?_pragma=journal_mode(WAL)&_pragma=busy_timeout(5000)&_pragma=foreign_keys(1)
```

- **WAL 模式**：审计日志写入与查询并发场景下读写不互斥，避免 `database is locked`
- **busy_timeout 5s**：导出进度更新与配置写入偶发竞争时的重试兜底
- 审计日志按保留期（默认 90 天）清理，控制单文件体积；清理器每日执行

- `rpt_report_param.option_sql` 由系统以**只读校验后执行**，结果两列（值、显示名）缓存 5 分钟

- 导出任务 `params` 存条件快照，Worker 重试时不再依赖前端传参

## 4. 驱动适配层设计

### 4.1 接口定义

```go
// datasource/driver.go
type Driver interface {
    // DSN 构建与连接
    BuildDSN(cfg model.Datasource, plainPwd string) (string, error)
    Open(dsn string, pool model.PoolConfig) (*sql.DB, error)

    // 元数据
    ListTables(db *sql.DB, keyword string) ([]TableMeta, error)
    ListColumns(db *sql.DB, table string) ([]ColumnMeta, error)
    ListIndexes(db *sql.DB, table string) ([]IndexMeta, error)
    ServerVersion(db *sql.DB) (string, error)

    // SQL 方言
    QuoteIdentifier(name string) string                  // 防注入的标识符引用
    Rebind(sql string, paramNames []string) (string, error) // :name → ?（Oracle 直通）
    WrapPaginate(sql, orderClause string, offset, limit int, ver DBVersion) (string, error)
    WrapKeyset(sql, orderCol, op string, lastVal any, limit int) (string, error)
    WrapCount(sql string) (string, error)                // 外层 SELECT COUNT(*)

    // 执行辅助
    EstimateRows(db *sql.DB, sql string) (int64, error)  // 导出量预估
    ValidateReadOnly(sql string) error                   // 语法级只读校验（尽力）
}

type DBVersion struct {
    Major int  // 如 Oracle 12 → 12
    Minor int
    Raw   string
}
```

### 4.2 五种驱动的方言矩阵

| 能力 | MySQL | Oracle (godror) | PostgreSQL | SQL Server | SQLite |
|------|-------|-----------------|------------|------------|--------|
| 占位符 | `?` | `:name`（直通） | `$1..$n` | `@p1..@pn` | `?` |
| 分页 | `LIMIT ? OFFSET ?` | 12c+：`OFFSET n ROWS FETCH NEXT m ROWS ONLY`；11g：`ROWNUM` 三层 | `LIMIT ? OFFSET ?` | `OFFSET ? ROWS FETCH NEXT ? ROWS ONLY`（2012+） | `LIMIT ? OFFSET ?` |
| 标识符引用 | `` `name` `` | `"NAME"`（大写敏感） | `"name"` | `[name]` | `"name"` |
| 表清单 | `information_schema.tables` | `all_tables` + `all_tab_comments` | `information_schema.tables` | `sys.tables` + `sys.extended_properties` | `sqlite_master` |
| 字段清单 | `information_schema.columns` | `all_tab_columns` + `all_col_comments` | `information_schema.columns` | `sys.columns` + 扩展属性 | `PRAGMA table_info` |
| 行数预估 | `EXPLAIN` 估算 / COUNT | `all_tables.num_rows`（需统计信息） | `pg_class.reltuples` | `sys.dm_db_partition_stats` | COUNT |
| 驱动 CGO | 否 | **是** | 否 | 否 | 否（modernc） |

### 4.3 Oracle 版本探测与方言适配

```
Manager.Get(dsID) 流程：
1. 连接池不存在 → Open 后执行 SELECT banner FROM v$version WHERE banner LIKE 'Oracle%'
2. 正则提取版本号 → DBVersion{12, 2}
3. 探测结果与 *sql.DB 一起缓存于 Manager（带 TTL 5min，避免多 goroutine 重复探测）
4. WrapPaginate 依据 DBVersion 分派：
   - Major >= 12 → FETCH 分页（需先包一层无 ORDER BY 子查询保证合法性）
   - Major < 12  → ROWNNUM 三层嵌套模板
```

ROWNUM 模板（11g 降级路径，供参考）：

```sql
SELECT * FROM (
  SELECT t_.*, ROWNUM rn_ FROM ( {原SQL+ORDER BY} ) t_
  WHERE ROWNUM <= :__end
) WHERE rn_ > :__start
```

### 4.4 Manager（连接池注册表）

```go
type Manager struct {
    mu    sync.RWMutex
    pools map[int64]*poolEntry // key: datasource_id
}
type poolEntry struct {
    db      *sql.DB
    version DBVersion
    loadedAt time.Time
}
```

- `Get(dsID)` 懒加载；数据源配置变更/停用时 `Invalidate(dsID)` 关闭旧池
- 全局空闲连接池数量上限（防用户配置过多数据源耗尽文件句柄）

## 5. 报表引擎设计

### 5.1 参数绑定流程

```
前端传参                     条件配置(rpt_report_param)            生成物
─────────                   ──────────────────────              ────────
{ "start_date": "2026-01-01",
  "dept": ["A","B"] }  ──► 逐条件项匹配：

  widget=dateRange, matchType=range, param=start_date
      → SQL 片段: (col BETWEEN :start_date_1 AND :start_date_2)   ← 注意：
        前端传 [start, end] 数组，引擎拆为两个绑定值
  widget=multiSelect, matchType=in, param=dept
      → SQL 片段: col IN (:dept_1, :dept_2, ...)  （按数组长度展开）

合并所有片段 → 由报表 SQL 作者负责在 SQL 中放入占位符对应的逻辑，
引擎不做 SQL 拼接改写，只做参数名 → 绑定值 的映射与类型转换
```

**关键设计决策**：引擎**不自动改写 WHERE**（自动拼 WHERE 对复杂 SQL 不可靠），采用两种模式由报表配置选择：

- **模式 A（默认）**：SQL 作者直接写 `:param`，引擎按配置做类型转换与必填校验后绑定。`IN`/范围类由作者写 `IN (:dept)`，引擎将数组绑定值展开为对应数量的占位符
- **模式 B（向导生成的表报表）**：引擎按条件配置自动生成 WHERE 片段附加到基础 SQL

### 5.2 类型转换表（绑定前执行）

| 控件 | 前端入参 | 绑定值 | 校验失败行为 |
|------|---------|--------|-------------|
| text | string | string | - |
| number | string | float64/int64（按元数据） | 400 提示 |
| date | `yyyy-MM-dd` | time.Time（按目标库格式化） | 400 提示 |
| dateRange | [start, end] | 两个 time.Time | 400 提示 |
| select | string | string | - |
| multiSelect | []string | []string → 展开绑定 | - |
| 动态默认值宏 | `${today}` 等 | 服务端计算后填充 | - |

### 5.3 查询执行流水线（QueryEngine.Query）

```
输入: reportID, params, page, pageSize, sortCol, sortDir, caller(登录/匿名)

1. 加载报表配置（带缓存：报表配置 LRU 60s）
2. 鉴权：登录用户查 rpt_role_report；匿名校验 public_token 哈希
3. ValidateReadOnly(sql_text)
   - 词法检查：拒绝 INSERT/UPDATE/DELETE/MERGE/DROP/ALTER/TRUNCATE/GRANT/EXEC/CALL...
   - 拒绝多语句（分号后仍有内容）
4. 参数校验与转换（5.2）→ 绑定值集合
5. Rebind（方言占位符转换；Oracle 直通）
6. 排序处理：sortCol 必须存在于 rpt_report_column 白名单 → 用 QuoteIdentifier 引用后拼 ORDER BY
7. WrapCount → 执行 COUNT（独立小查询，超时 5s）
8. WrapPaginate → 执行数据查询
   - context.WithTimeout(report.query_timeout)
   - defer rows.Close()
9. 组装结果：列元数据([]ColMeta) + 行数据([][]any, 值统一转 JSON 安全类型)
10. 深分页切换：page*pageSize > 10000 且报表配置了 keyset 列 → 返回游标提示，
    前端下一页改传 cursor（WrapKeyset 路径）
11. 写审计日志（异步 goroutine，不阻塞响应）
```

### 5.4 只读防护层次

| 层 | 手段 | 说明 |
|----|------|------|
| 1 | 词法黑名单 | 快速拦截明显写操作 |
| 2 | 多语句检测 | 仅允许单条语句 |
| 3 | 连接层 | 文档建议数据源使用只读账号；Oracle 可加 `ALTER SESSION SET ... READ ONLY`（可选配置项 `readonly_session`） |
| 4 | 超时+行限 | 兜底资源保护 |

## 6. 导出子系统设计

### 6.1 双模式决策流程

```
用户点击导出 ──► POST /export (同步接口)
                 │
                 ├─ EstimateRows
                 │    ├─ 预估 ≤ 10000 行 → 同步流式导出：
                 │    │   直接 Rows 流式读 → StreamWriter/Bufio 写 HTTP 响应
                 │    │   （Content-Disposition: attachment）
                 │    │
                 │    └─ 预估 > 10000 行 或 COUNT 超时/失败
                 │         → 返回 202 {suggest: "async"}，前端转调
                 │           POST /export-async 创建任务
                 │
异步任务执行（Worker）：
  pending ──► running ──► done
     │           │
     │           └──► failed（错误信息入库，可重试）
     └──► canceled（用户取消/超量截断标注）
```

### 6.2 Worker 执行流程

```
Worker(quota=2, 从任务通道取任务):
1. status: pending→running, 记录 started_at
2. 按任务 params 重建 QueryEngine 上下文（复用 5.3 步骤 3~6，不分页）
3. rows, _ := db.QueryContext(ctx)   // ctx 超时 = min(报表超时, 任务级上限如 2h)
4. 循环 fetch（每批 1000 行 buffer）:
     ├─ 每 10000 行: 更新 exp_export_task.done_rows（进度）
     ├─ xlsx: StreamWriter.Flush 由 excelize 内部管理；
     │        行数达 1,048,575 → 关闭当前文件，新开 part 文件（file_parts++）
     ├─ csv:  bufio.Writer 直写
     ├─ total_rows ≥ export_limit → 停止，标注 truncated
     └─ ctx.Done() → 失败退出，清理半成品文件
5. 生成文件落盘 export/{task_no}.xlsx / .csv / .part1.xlsx...
6. status→done, finished_at, total_rows 入库
7. 若为异步任务且创建人是登录用户 → 可选 WebSocket/轮询通知（本期轮询）
```

### 6.3 内存与性能控制

| 项 | 策略 |
|----|------|
| 行缓冲 | 每批 1000 行 `rows.Next()` 循环读，值即取即写，不累积 |
| xlsx | `excelize.NewStreamer` 流式写，共享字符串表禁用（`SharedStringMode=false`），内存 O(1) |
| 驱动 fetch | godror 设 `FetchArraySize=1000`；MySQL 设 `interpolateParams` 减少往返 |
| 并发 | Worker 上限 2（可配），任务队列满时 429 拒绝新任务 |
| 慢 SQL | 分片模式（可选，报表配置 `export_slice_col`）：按主键 `WHERE id > last ORDER BY id LIMIT 100000` 循环，每片独立游标 |

### 6.4 文件管理

- 目录：`{data_dir}/export/`，文件名 `{task_no}.xlsx`（拆分则 `.part{n}`）
- 下载鉴权：登录用户 → 校验 `created_by`；匿名 → 一次性签名 URL（HMAC(task_no+exp)），10 分钟有效
- 清理器：每 6 小时扫描 `finished_at + 7d` 的任务，删除文件并将任务标记 `expired`（保留记录）

## 7. 认证与公开访问设计

### 7.1 JWT 设计

```
Access Token:  HS256, exp=2h
  claims: { sub: userId, name: username, role: "admin|user", typ: "access" }
Refresh Token: exp=7d, typ="refresh"，服务端校验用户状态
登录锁定: fail_count≥5 → locked_until = now+10min
```

### 7.2 公开访问机制

```
管理员开启报表公开访问:
  POST /api/reports/:id/publish  {is_public: true}
  → 服务端生成 public_id(12位随机) + public_token(32位随机, 库存SHA-256)
  → 返回明文 token 一次，链接: /r/{public_id}?token={token}

匿名请求流:
  GET /r/{public_id}?token=xxx          → 前端报表页（校验 token 有效后渲染）
  POST /api/pub/{public_id}/query       (Header: X-Report-Token: xxx)
     → PublicToken 中间件:
        1. 查报表: is_public=1 且 status=published
        2. SHA256(token) 与库中哈希比对
        3. IP 限流: 令牌桶 30次/分钟/IP（可配）
        4. 注入 caller{anonymous, reportID}，进入 5.3 流水线（跳过角色校验）
```

- 公开接口仅暴露 `query` / `option-values`（下拉选项）/（可选）`export`，**不暴露**报表 SQL、数据源信息
- 重置令牌：`POST /api/reports/:id/rotate-token`（管理员）

### 7.3 角色与权限（RBAC，多角色 + 菜单/按钮权限点）

**模型**

```
用户 ──< sys_user_role >── 角色 ──< sys_role_menu >── 菜单/权限点
   （多对多，权限取并集）        （M 目录 / C 页面 / F 按钮）

角色 ──< rpt_role_report >── 报表        （报表可见性，与报表配置页「可见角色」同表）
```

- `sys_role.role_key` 是稳定标识，所有授权数据都引用它；角色标识**创建后不可修改**，避免授权悬空
- `sys_user.role` 仅保留为「主角色」（展示、JWT claims），真实授权以 `sys_user_role` 为准
- `admin` 角色为隐式超级管理员：权限集直接是通配 `*`，不受菜单授权限制，也不会被误删（内置）

**权限点命名规范**：`模块:对象:动作`，如 `system:user:create`；页面级权限点与页面菜单节点绑定。

| 模块 | 权限点 |
|------|--------|
| 报表查看 | `report:view` |
| 报表配置 | `report:update`（页面）、`report:create`、`report:delete`、`report:publish`、`report:public`、`report:preview` |
| 数据源 | `datasource:list`（页面）、`datasource:create`、`datasource:update`、`datasource:delete`、`datasource:test` |
| 字典 | `dict:list`（页面）、`dict:create`、`dict:update`、`dict:delete` |
| 用户 | `system:user:list`（页面）、`create`、`update`、`delete`、`resetPwd`、`assignRole` |
| 角色 | `system:role:list`（页面）、`create`、`update`、`delete`、`assignMenu`、`assignReport` |
| 菜单 | `system:menu:list`（页面）、`create`、`update`、`delete` |

**鉴权链路**

```
请求 → JWTAuth：校验 access token（取 uid）
              → rbac.RolesOf(uid)：每次请求按库中的用户-角色关联解析（收回角色立即生效）
              → rbac.PermsOf(roles)：角色→权限点集合，内存缓存，授权变更后 Invalidate
         → RequirePerm("report:create")：perms 含 * 或该点才放行
前端：/api/auth/me 一次拿齐 {user, roles, perms, menus}，
      模板用 can('report:create') 控制按钮显隐，rs-nav 组件按 menus 渲染顶栏
```

- 报表数据权限（能否查/导出某张报表）仍由 `rpt_role_report` 判定：**任一角色被授权**即可，管理员不受限
- 角色停用（`status=0`）＝该角色所有权限立即失效，其他角色不受影响
- 权限变更只清缓存，不需要用户重新登录

**当前用户契约**

```
GET /api/auth/me
{
  "user":  { "id":2, "username":"zhangsan", "displayName":"张三", ... },
  "roles": [ {"roleKey":"report_dev","roleName":"报表开发"} ],
  "perms": [ "report:view", "report:update", ... ],   // 管理员为 ["*"]
  "menus": [ {"id":1,"menuName":"报表中心","path":"/reports","children":[]}, ... ]
}
```

**升级与兼容**

- 启动时 `seedRBAC`：写入 admin/user 两个内置角色与默认菜单树（固定 ID，幂等）
- `BackfillUserRoles`：为没有角色关联的老账号按 `sys_user.role` 补一条关联，并按需补建角色，避免升级后登录即失权
- 新增一个功能页面的标准动作：菜单管理里加 C 节点（填 `perms`）→ 加 F 节点声明按钮权限点 → 角色管理勾选 → 代码里 `RequirePerm("x:y:z")` + 模板 `can('x:y:z')`
