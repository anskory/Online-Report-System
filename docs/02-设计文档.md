## 1. 设计概述

本文档为《01-开发文档》需求的技术设计，覆盖：系统库结构、驱动适配层、参数绑定与查询引擎、导出子系统、认证与公开访问、API 契约、前端设计、配置与部署。

关键约束（设计前提）：

| 约束 | 设计影响 |
|------|---------|
| Oracle 必须支持，且要能交叉编译 | **默认纯 Go go-ora**（`Paginate` 按版本分发）；godror 仅 `-tags oracle` 可选 |
| Windows / Linux / macOS 分发 | 默认 `CGO_ENABLED=0`；单二进制 + config + data 目录即可运行 |
| 百万级导出 | 同步流式 + 异步任务双模式；xlsx 超单 Sheet 上限自动拆 Sheet |
| 报表可公开访问 | `public_id` + 令牌哈希 + 独立公开路由组 + IP 限流 |
| 默认 Excel 导出 | excelize StreamWriter 主通道，CSV 备选 |
| 配置化查询条件 | 参数名（绑定变量）与结果集列名（可中文）解耦；支持自动装配 |

### 2.2 依赖方向

- `api` → `service` → `datasource`；`export` 复用 `QueryEngine`；`dict` 被 `query_engine`（选项来源、列翻译）与 `column_config` 共用

## 3. 系统库设计

### 3.1 存储与运行参数

系统库默认 **SQLite（glebarez/sqlite，底层纯 Go modernc），单文件 `./data/report_sys.db`**，MySQL 可选（改 `sys_db.driver/dsn`）。

服务启动后对连接显式执行 PRAGMA（不依赖 DSN 语法，换驱动也成立）：

```go
db.Exec("PRAGMA journal_mode = WAL")   // 审计写入与查询不互斥，避免 database is locked
db.Exec("PRAGMA busy_timeout = 5000")  // 写竞争重试兜底
db.Exec("PRAGMA foreign_keys = ON")
```

表结构由 GORM `AutoMigrate` 生成（方言无关）。注意 SQLite 限制：**不允许给已有表新增「NOT NULL 且无默认值」的列**——模型字段一律带 `default:`，启动失败时给出明确提示。

### 3.2 表清单

## 4. 驱动适配层

### 4.1 接口（实际签名）

```go
type Driver interface {
    BuildDSN(cfg ConnConfig) (string, error)
    Open(dsn string, cfg ConnConfig) (*sql.DB, error)
    ServerVersion(ctx context.Context, db *sql.DB) (string, error)
    ListTables(ctx context.Context, db *sql.DB, keyword string) ([]TableMeta, error)
    ListColumns(ctx context.Context, db *sql.DB, table string) ([]ColumnMeta, error)
    QuoteIdentifier(name string) string
    Rebind(query string) string                  // :name → 目标库占位符（Oracle 直通）
    Paginate(query string, offset, limit int) string
}
```

- `TableMeta{Name, Comment, TableType}`、`ColumnMeta{Name, DataType, Nullable, Default, IsPK, Comment}`
- `ConnConfig` 由 `model.Datasource` 转换，密码明文仅在内存短存
- Oracle 两个实现（`oracle_cgo.go` / `oracle_purego.go`）各自提供 `PaginateFor(version, query, offset, limit)`，编译期断言 `var _ Driver = ...` 保证两条路线接口一致
- 新增数据库 = 实现接口 + 在 `Manager` 注册，不改引擎

### 4.2 方言矩阵

| 能力 | MySQL | Oracle（go-ora / godror） | PostgreSQL | SQL Server | SQLite |
|------|-------|--------------------------|------------|------------|--------|
| 占位符 | `?` | `:name` 直通 | `$1..$n` | `@p1..@pn` | `?` |
| 分页 | `LIMIT ? OFFSET ?` | ≥12c：`OFFSET n ROWS FETCH NEXT m ROWS ONLY`；≤11g：ROWNUM 三层 | `LIMIT ? OFFSET ?` | `OFFSET n ROWS FETCH NEXT m ROWS ONLY` | `LIMIT ? OFFSET ?` |
| 标识符 | `` `name` `` | `"NAME"` | `"name"` | `[name]` | `"name"` |
| 表清单 | `information_schema.tables` | `all_tables` + `all_tab_comments` | `information_schema.tables` | `sys.tables` + 扩展属性 | `sqlite_master` |
| 字段清单 | `information_schema.columns` | `all_tab_columns` + `all_col_comments` | `information_schema.columns` | `sys.columns` + 扩展属性 | `PRAGMA table_info` |
| CGO | 否 | **go-ora 否 / godror 是** | 否 | 否 | 否 |

### 4.3 跨模式表名（v1.0 增补）

字典与元数据查询允许 `模式名.表名`（如 `FGPESE0.SYS_DICT_TYPE`）：

- 校验：`ValidateTableRef` 允许「标识符」或「标识符.标识符」（含中文，禁止引号/分号/其他符号）；`ValidateColumnName` 不允许点号
- 各驱动 `ListColumns` 按需拆分：MySQL 按 `table_schema`、PostgreSQL 按 `nspname`、SQL Server 先保存全限定名再按 `SCHEMA_NAME` + `OBJECT_ID`、Oracle 直接拼 `OWNER.TABLE`
- 踩坑记录：SQL Server 曾在拆分后把裸表名传给 `OBJECT_ID` 导致找错表，已改为拆分前保存全名

### 4.4 Oracle 版本探测

```
Manager.Get(dsID)：
1. 池不存在 → Driver.Open 建池
2. ServerVersion(db) 执行 SELECT banner FROM v$version WHERE banner LIKE 'Oracle%'
3. OracleMajorVersion(banner) 正则提取主版本 → 缓存于 poolEntry
4. PaginateFor(version, ...) 分派：
     major >= 12 或解析失败 → OFFSET/FETCH
     major <= 11           → ROWNUM 三层嵌套
```

ROWNUM 模板：

```sql
SELECT * FROM (
  SELECT t_.*, ROWNUM rn_ FROM ( {原SQL + ORDER BY} ) t_
  WHERE ROWNUM <= :__end
) WHERE rn_ > :__start
```

### 4.5 连接池

- `poolEntry{db *sql.DB, version string, loadedAt}`，`RWMutex` 保护，按 `datasource_id` 懒加载
- 数据源增删改/停用后 `Invalidate(id)` 关闭旧池，下次访问重建
- 池参数按数据源（MaxOpen 20 / MaxIdle 5 / Life 3600s 默认），Oracle 默认保守，避免占满会话数

### 4.6 SQL 分词状态机（核心基础组件）

`driver.go` 的 `splitSQLSegments` 按「单引号字符串字面量 + `--` 行注释 + `/* */` 块注释」切分，所有参数解析/替换都在**字面量与注释之外**进行：

- 避免把 `TO_DATE(x,'YYYY-MM-DD HH24:MI:SS')` 里的 `:MI`/`:SS` 当参数
- 避免注释掉的旧占位符（`-- 旧写法 :MAT_STATUS`）参与绑定，导致**绑定位次错位**
- 基于同一状态机提供 `MaskStrings` / `MaskComments` / `MapOutsideStrings` / `ExtractParamNames`

> 该组件是 v1.0 修复「字典选择后报 arg_empty_name」的根因所在：三类绑定错位（字面量误判、Oracle 去重、级联绑 nil）全部由此而来。改动绑定逻辑前必须读懂这一层。

## 5. 报表引擎设计

### 5.1 参数绑定：两种模式并存

| 模式 | 触发 | 行为 |
|------|------|------|
| A 内联绑定 | SQL 中已写 `:param` | 引擎按配置做类型转换、必填校验后绑定；数组值展开为 `:name_i` |
| B 自动装配 | SQL 中**未**写该 `:param` | `autoWrapSQL` 按条件配置自动拼 `WHERE` / `AND`，用 `QuoteIdentifier(columnName)` + 绑定变量 |

- 两种模式可在同一张报表混用（部分条件内联、部分自动）
- 自动装配的列名取 `column_name`，为空回退 `param_name`；**列名允许中文**（双引号包裹），参数名必须是合法标识符——这就是「条件 钢板号 未在 SQL 中书写占位符」报错的修复方式
- 保存与查询两个环节都会做 `validateParamsInSQL`，SQL 里写了占位符但没配条件、或条件名非法，都会在保存时明确提示

### 5.2 绑定顺序（Oracle 关键差异）

```
orderedArgs(dbType, sqlText, binds)：
1. ExtractParamNames 按 SQL 中首次出现顺序取参数名（跳过字面量/注释）
2. Oracle：按首次出现去重（同名占位符只绑一次，go-ora 位置绑定语义）
   其他库：保留重复（? 逐个绑定）
3. 生成 args []any 与 names []string（用于诊断）
```

- `go-ora` 的 `_exec` 使 `useNamedPars=false`，按位置绑定；与 Oracle SQL 中同名命名参数只算一个绑定变量的语义一致
- 绑定失败时 `requeryErr(stage, sql, names, binds, err)` 输出「阶段 + 参数顺序 + 值摘要 + SQL 摘要」，把 ORA-01036 这类错误从「无解」变成「可定位」
- `hintORA` 对 ORA-01036（绑定变量个数/名称不符）、ORA-01008（未绑定全部变量）、ORA-01722（无效数字）追加中文排查建议

### 5.3 类型转换（绑定前）

| 控件 | 前端入参 | 处理 |
|------|---------|------|
| text | string / string[] | 多值时按 `matchType`：eq → `IN` 展开；like → 明确报错 |
| number | string / number | 转 float64/int64；非法值 400 并指条件名 |
| date | `yyyy-MM-dd` | 目标库格式化 |
| dateTime | `yyyy-MM-dd HH:mm:ss` | 同上 |
| dateRange | `[start, end]` | 拆两个绑定值（`_1` `_2`） |
| select | string | 直传 |
| multiSelect | string[] / 逗号串 | 统一为数组，`IN` 展开 |
| 空值 | `''` / `null` / `[]` | 视为「未填」：有默认值则回退默认，无则不参与过滤 |

### 5.4 执行流水线（`QueryEngine.Execute`）

```
1. 取报表配置（含 params / columns）
2. 鉴权：登录用户查 rpt_role_report；匿名校验 public_id + token 哈希
3. validateSQLText：只读校验（拒绝 INSERT/UPDATE/DELETE/MERGE/DROP/ALTER/TRUNCATE/GRANT/CALL、多语句）
4. buildBinds：校验必填、类型转换、多值拆分、空值回退默认
5. autoWrapSQL：未内联的条件自动补 WHERE/AND
6. Rebind + orderedArgs：方言占位符与绑定顺序
7. COUNT：独立超时（默认 5s）+ 30s 缓存；超时降级 total=-1（总数未知）不阻塞数据
8. Paginate（按 Oracle 版本/各库方言）→ QueryContext（报表超时）→ 逐行扫描
9. 结果整形：值统一为 JSON 安全类型（time → 字符串、[]byte → string、decimal → float/字符串）
10. 字典翻译：按列配置 dictCode 做 值→标签（列表/导出格式分别处理）
11. 审计异步写入（不阻塞响应）
```

### 5.5 只读与安全防护

| 层 | 手段 |
|----|------|
| 1 | 词法黑名单（写操作关键字）+ 多语句检测 |
| 2 | 所有值走绑定变量，不做字符串拼接 |
| 3 | 排序/过滤标识符走白名单 + `QuoteIdentifier` |
| 4 | 超时 + 行数上限 + COUNT 独立超时 |
| 5 | 建议数据源使用只读账号（部署建议） |

### 5.6 选项 SQL（下拉级联）

- `optionType=sql` 时执行配置的两列查询（值、标签），最多 200 行
- SQL 中可引用其它条件的 `:param`，实现「选分厂 → 刷新产线」的级联
- `optionType=dict` 时按字典编码取选项（可再按字典类型筛选）
- 前端进入报表页即预载全部下拉选项（不再等展开才请求），字典选项有并发占位缓存

### 5.7 展示列与用户列配置

- 展示列（`rpt_report_column`）是**报表级**定义：列名、格式、字典翻译、默认宽度/显隐、是否可排序
- 列配置（`rpt_column_config`）是**用户级**覆盖：宽/序/显隐/冻结，按 `(report_id, user_id)` 存 JSON；非法列名在应用时被过滤，避免历史配置导致报错

## 6. 导出子系统

### 6.1 双模式

```
POST /api/reports/:id/export {format, params, sortCol, sortDir}
  │
  ├─ 行数 ≤ export.sync_row_limit（默认 1 万）
  │    → 同步流式：Rows 逐批读 → StreamWriter/bufio 直写 HTTP 响应
  │
  └─ 超过阈值
       → 建 exp_export_task（queued）+ 入队 → 202 返回 taskId
          Worker：queued → running → done / failed（错误入库）
          前端轮询 GET /api/export-tasks/:id 看 progress
```

### 6.2 Worker 与进度

```
Worker（export.workers，默认 2）：
1. 取任务 → status=running
2. 用 params_snapshot 重建查询上下文（复用 5.4 的 3~6 步，不分页）
3. 流式写：
     xlsx：excelize StreamWriter；单 Sheet 达 xlsx_sheet_max_row（默认 100 万）自动新开 Sheet2…
     csv ：encoding/csv + bufio（UTF-8 BOM，Excel 打开不乱码）
   每 1 万行更新 progress / done_rows
4. 达到 exportLimit（默认 500 万）截断并标注
5. 落盘 data/exports，写 file_path / file_size / finished_at
```

### 6.3 文件管理

- 目录：`export.dir`（默认 `./data/exports`）
- 下载：登录用户校验 `created_by`；公开报表走令牌校验，且要求 `pub_allow_export=1`
- 清理：`export.retention_days`（默认 7 天），定时删除过期文件（每 6 小时）
- 文件名：`报表名_yyyyMMdd_HHmmss.xlsx`（非法字符已 sanitize）

### 6.4 内存控制

| 项 | 策略 |
|----|------|
| 行缓冲 | 逐行读、即取即写，不累积 |
| xlsx | StreamWriter，内存 O(1) |
| 并发 | Worker 数可配，队列满拒绝新任务 |
| 计数 | `EstimateRows` 先行，超阈值直接转异步，避免同步请求超时 |

## 7. 认证、权限与公开访问

### 7.1 JWT

```
Access Token：HS256，exp=2h，claims{sub: userId, name: username, role: 主角色}
Refresh Token：exp=7d，typ=refresh，服务端校验用户状态
登录锁定：fail_count ≥ login_max_fail（5）→ locked_until = now + login_lock_minutes（10min）
```

- `JWTAuth` 校验 token → 取 uid → **每次请求按库解析角色与权限点**（角色收回立即生效，无需重新登录）
- 密码 bcrypt；数据源密码 AES-256-GCM（`crypto.DeriveKey(aes_key)`）

### 7.2 公开访问

```
开启：POST /api/reports/:id/public
  → 生成 public_id（12 位）+ 明文 token（一次性返回）
  → 库存 SHA-256(token)，is_public=1
链接：/r/{public_id}?token={token}（前端 Public.vue 读取 query 并转成请求头）

匿名请求：
  POST /api/pub/{publicId}/query
  Header: X-Report-Token: {token}
    → checkToken：
       1. publicId/token 非空
       2. IP 限流：滑动窗口 30 次/分钟（内存，按 ClientIP）
       3. CheckPublicToken：SHA-256 比对 + is_public=1
       4. 注入匿名调用者，跳过角色校验，进入 5.4 流水线
```

- 公开接口只返回列与数据，**不下发 SQL、数据源等配置**
- 导出受 `pub_allow_export` 控制（默认关闭）
- 关闭公开访问：`is_public=0` 且清空 `public_token`，旧链接立即失效
- 匿名列配置统一用 `user_id=0`

### 7.3 RBAC

```
用户 ──< sys_user_role >── 角色 ──< sys_role_menu >── 菜单/权限点
角色 ──< rpt_role_report >── 报表（可见性）
```

- `role_key` 为稳定标识，授权数据只引用它；`sys_user.role` 仅作主角色展示
- `admin` 隐式 `*`，不受菜单授权限制；`builtin=1` 不可删除
- 权限点命名 `模块:对象:动作`：`report:view/create/update/delete/publish/public/preview`、`datasource:list/create/update/delete/test`、`dict:list/create/update/delete`、`system:user:*`、`system:role:*`、`system:menu:*`
- 鉴权链路：`JWTAuth` → 解析角色 → 权限集（缓存，变更 Invalid）→ `RequirePerm("x:y:z")` 放行；前端 `can('x:y:z')` 控制按钮
- 报表可见性：任一角色被授权即可查/导出；管理员不受限

**`/api/auth/me` 契约**

```json
{
  "user":  { "id": 2, "username": "zhangsan", "displayName": "张三" },
  "roles": [ { "roleKey": "report_dev", "roleName": "报表开发" } ],
  "perms": [ "report:view", "report:update" ],
  "menus": [ { "id": 1, "menuName": "报表中心", "path": "/reports", "children": [] } ]
}
```

**升级兼容**

- 启动 `seedRBAC`：写入 admin/user 内置角色与默认菜单（幂等）
- `normalizeMenuPaths`：历史 `/ui/xxx.html` 菜单路径统一改写为 `/xxx`
- `BackfillUserRoles`：无角色关联的老账号按 `sys_user.role` 补关联，避免升级即失权

## 11. 部署设计

### 11.1 构建矩阵

| 平台 | 产物 | Oracle 支持 | 说明 |
|------|------|------------|------|
| Windows amd64 | `report-server.exe` | 优先 godror（CGO，探测 gcc + Instant Client），失败自动降级纯 Go | 若为 CGO 版，随包分发 `oci.dll` 等 DLL |
| Linux amd64/arm64 | `report-server-amd64/arm64` | 纯 Go | 静态可执行，无外部依赖 |
| macOS amd64/arm64 | 同上 | 纯 Go | Apple 芯片选 arm64，首次运行需去 quarantine |
| Docker | 镜像 | 可选 `WITH_ORACLE=1` | 见 `backend/deploy/` |

`一键编译.bat → build-all.ps1` 六步：定位工具链 → 前端构建 → `go mod tidy` → 探测 CGO/Oracle 环境 → 交叉编译 → 组装 `app/{windows,linux,macos}`（config、data、启动脚本、使用说明）。

### 11.2 运行时目录

```
{install_dir}/
├── report-server(.exe) / report-server-amd64
├── config.yaml
├── data/
│   ├── report_sys.db        # 系统库（SQLite）
│   └── exports/             # 导出文件
├── logs/server.log          # 启动脚本重定向
├── 启动服务.bat / 后台启动.bat / 停止服务.bat   # Windows
└── start.sh / stop.sh                          # Linux/macOS
```

### 11.3 Nginx 反向代理要点

- `proxy_buffering off`（导出大文件避免 `ERR_CONTENT_LENGTH_MISMATCH`）
- `proxy_read_timeout 300s`（同步导出耗时）
- **`client_body_temp` / `proxy_temp` 目录归属必须与 worker 用户一致**，否则上传/代理直接 500（实测踩坑）
- 对外建议启用 HTTPS，`X-Forwarded-For` 透传（公开访问限流按真实 IP）

### 11.4 常驻方式

- Linux：systemd（`Restart=always`）或 `./start.sh -d`（nohup + pid 文件 + logs）
- Windows：`后台启动.bat`（最小化窗口写日志）/ nssm 注册服务
- 注意：`start.sh` 里可执行文件名是 `report-server-amd64/arm64`，`nohup ./report-server` 会 Exit 127

## 12. 错误响应约定

统一 `{"code": <业务码>, "msg": "<可读信息>"}`，HTTP 状态码同步语义：

| code | HTTP | 含义 |
|------|------|------|
| 0 | 200 | 成功 |
| 1001 | 401 | 未登录 / Token 失效 |
| 1002 | 423 | 账号锁定 |
| 1003 | 403/401 | 无权限 / 公开令牌缺失或无效 |
| 2001 | 400 | 参数校验失败（msg 指明条件名） |
| 2002 | 400 | 非只读 SQL 被拦截 |
| 2003 | 400 | 排序列不在白名单 |
| 3001 | 504 | 查询超时 |
| 3002 | 429 | 限流 / 导出并发已满 |
| 3003 | 400 | 导出超行数上限 |
| 4001 | 500 | 数据源连接失败 |
| 4002 | 500 | 元数据扫描失败 |
| 5000 | 500 | 系统内部错误 |

实际实现中，业务错误以 `msg` 为主（前端 `RS.alertErr` 直接展示），code 用于程序分支判断。

## 15. 安全设计清单

| 项 | 措施 |
|----|------|
| 密码 | bcrypt（cost 10）；登录失败计数 + 锁定 |

| 传输 | 建议 HTTPS（反代终止） |
| 审计 | 登录/查询/导出/配置变更入库（含 IP、耗时、SQL 摘要） |

## 16. 与初版设计的差异（实现回填）

| # | 初版设计 | 实际实现 | 原因 |
|---|---------|---------|------|
| 1 | Oracle 统一 godror（CGO），唯一 CGO 依赖 | 默认 go-ora 纯 Go，godror 可选 | 让 Windows/Linux/macOS 都能零依赖交叉编译，降低交付门槛 |
| 2 | keyset 游标深分页 | 仅 OFFSET 分页 + COUNT 缓存/超时降级 | 复杂度与收益权衡；行数上限已能兜底 |
| 3 | 导出分片查询（按主键切片） | 单游标流式 + 行数上限 | 实测流式足够；分片对复杂 SQL 不可靠 |
| 4 | 匿名下载一次性签名 URL | `X-Report-Token` 校验 + 归属校验 | 少一套签名机制，权限模型更统一 |
| 5 | WebSocket 进度推送 | 前端轮询 `GET /api/export-tasks/:id` | 实现简单、反向代理友好 |
| 6 | SqlEditor 用 CodeMirror 6 | 自研双图层高亮 + 补全 | 免引入重依赖，包体更小、可控性更好 |
| 7 | 元数据 TTL 缓存 + 索引浏览 | **v1.2 已实现**：TTL 300s 缓存 + 单飞 + 内存关键字过滤 + 索引清单接口 | 见第 18 章 |
| 8 | 审计日志自动清理 | **v1.2 已实现**：分批删除 + 每 6 小时 + 查询/导出接口 + 页面 | 见第 18 章 |
| 9 | 独立 `export` 包 | 导出逻辑在 `service/export.go` | 避免循环依赖，复用 `QueryEngine` |
| 10 | 公开访问全局配置段 `public_access.*` | 限流常量 30 次/分，导出按报表 `pub_allow_export` | 配置面收敛 |

## 17. 后续优化建议

1. **深分页**：为大数据量报表提供可选的 keyset 游标（需报表配置排序列）
2. **导出分片**：超大结果集按主键分片，降低单游标长时间占用
3. **报表首页看板**：今日查询次数、活跃报表、数据源健康度（需新增统计接口）
4. **导出中心页面**：目前任务列表接口已有，前端可加独立「导出中心」页
5. **条件草稿增强**：向导目前只生成等值条件，日期区间（`:begin`/`:end`）可后续补齐
6. **日志归档**：单机场景 90 天保留已够；大流量部署可考虑按类型分表或落文件

## 18. v1.2 增量设计（FR-07 / FR-11 / FR-19）

> 详细方案见 `docs/03-完善方案-FR07-FR11-FR19.md`，本节只记录落地后的关键决策。

### 18.1 元数据缓存（FR-07）

| 项 | 实现 |
|----|------|
| 缓存粒度 | 表清单按数据源整体缓存（keyword 在内存过滤）；字段清单按 `数据源ID + 小写表名` |
| 一致性 | TTL `meta.cache_ttl_sec`（默认 300s）；`refresh=1` 强制重扫；空结果不写缓存；`POST /api/datasources/:id/meta/clear` 手动清（DDL 后不必等 TTL） |
| 并发 | 单飞（`inflight` map + `chan struct{}`）：同 key 并发只扫一次；扫描用 `context.WithoutCancel` + 60s 超时，避免首个请求断开拖垮其他等待者 |
| 失效 | `DatasourceService.OnChange(meta.Invalidate)`，在 service 写入口内部触发（避免包内循环依赖） |
| 失效竞态 | `Invalidate` 同时把该数据源的「失效代数」+1；扫描开始取代数快照、写回前比对，不一致就丢弃结果——否则改数据源时正好有旧扫描在途，旧数据会被写回缓存，表现为「失效没生效」 |
| 响应 | `{items,total,truncated,cached,ageSec}`，`meta.table_limit` 默认 3000，可用 `?limit=` 单次覆盖 |
| 索引 | 驱动可选接口 `IndexProvider.ListIndexes`；Oracle 两个驱动共用 `oracle_common.go` 一份 SQL |

### 18.2 表生成报表（FR-11）

- **只生成不落库**：`POST /api/report-wizard/generate`；保存仍走 `POST /api/reports`，权限/审计/默认授权只有一份。
- 路径用 `/api/report-wizard/generate` 而非 `/api/reports/wizard/generate`：gin 的静态段与 `:id` 参数段不能共存于同一层级。
- 生成规则：标识符「标准 ASCII 且非保留字」裸写、否则用 `driver.QuoteIdentifier`；表名先过 `ValidateTableRef`；默认按主键 `ORDER BY`（无则告警）；**不生成 LIMIT**（分页由引擎接管）；条件草稿参数名 `condN`、列名放 `columnName` 走自动装配。
- 长度约束：结果列名/别名超过 64 字符直接报错（`ReportColumn.ColName` 列宽 64，SQLite 不报错但 MySQL 严格模式会插入失败）；字段注释过长时展示名截断到 64 字符。
- 规模约束：字段数硬上限 2000（高于 Oracle 1000 / PG 1664 / SQLite 2000 的单表列数，只拦异常请求）；生成 SQL 超 60000 字节（对应 MySQL `TEXT` 64KB）时报「SQL 过长」并说明是字段太多，而不是等到保存时抛 `Data too long`。宽表是常态——制造实绩表常有几百上千列，不能靠「分批建报表」绕过。
- 前端渲染：字段表格按 100 行/页分页，`el-table` 无虚拟滚动，上千行一次渲染会卡住弹窗。
- 可测性：`WizardService` 依赖的元数据能力抽为 `wizardMeta` 接口，单测用替身，无需连库。

### 18.3 操作日志（FR-19）

| 项 | 实现 |
|----|------|
| 写入 | 有界队列（`log.audit_queue_size`，默认 2048）+ 单 worker，攒 200 条或 1s 批量 `CreateInBatches`；满队列丢弃并计数（`/api/health` → `auditDropped`）；`log.audit_sync=true` 可切同步写排障 |
| 字段 | 新增 `module/target/user_agent/trace_id/err_msg`（全部带 `default:''`，兼容 SQLite 增量加列）；复合索引 `(log_type, created_at)` |
| 成功/失败 | `AuditEntry.Success` 是 `*bool`：**nil 视为成功**，只有显式传 `false` 才记失败。若用 bool 零值，任何忘记赋值的埋点都会变成「失败日志」 |
| 成败都记 | 查询与导出失败也写日志（带 `errMsg` 与耗时）——失败恰恰是最需要复盘的场景 |
| 目标快照 | `Target` 存报表名/数据源名/字典名/用户名/角色名/菜单名，对象删除后日志仍能读懂；删除类操作一律在删之前先取名字（取不到退回 `#ID`） |
| 清理 | `StartCleanup`：启动先清一次，之后每 6 小时；每批 5000 行（先 SELECT id 再 `DELETE ... IN`，避开各库 `DELETE LIMIT` 差异） |
| 查询 | `GET /api/system/audit-logs`（pageSize ≤ 200）、`/stats`、`/export`（CSV 流式，1000/批，上限 10 万行）、`DELETE ?before=` |
| 菜单 | `ensureExtraMenus` 按「ID 或 perms」幂等补齐；`defaultMenus` 只在菜单表为空时执行，老库必须靠这一步 |
| 埋点补齐 | 字典增删改、登录失败/锁定/停用、数据源连接测试（含保存前试连）、报表删除时的名称快照；用户/角色/菜单管理（Module 分别为 `user`/`role`/`menu`，13 处埋点全部带 Target） |
