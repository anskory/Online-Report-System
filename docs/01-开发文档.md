## 1. 项目概述

### 1.1 项目背景

企业内部经常需要针对业务数据库做临时性、多样化的数据查询与统计。传统做法是为每个报表需求单独开发页面，周期长、维护成本高。本项目目标是构建一个**基于配置的在线报表系统**：由管理员在 Web 界面上配置数据源、SQL、查询条件与展示列，即可快速生成一个可查询、可导出的报表页面，无需改代码。

### 1.2 项目目标

- 报表"配置即上线"：新增一张报表不需要重新编译、发版
- 支持接入多种类型、多个实例的数据库（**必须支持 Oracle**）
- 提供表/字段元数据浏览能力，辅助编写 SQL
- 查询条件（输入框、下拉、日期范围等）完全由配置驱动
- 支持百万级结果集导出（流式 + 异步任务）
- 技术栈统一为 Go，单机单服务部署，预留 Docker 化能力

### 1.3 非目标（本期不做）

- 复杂报表设计器（拖拽式、交叉表、图表可视化）—— 后续版本考虑
- 定时任务调度、报表订阅推送
- 细粒度的行列级数据权限（本期仅做菜单/报表级权限）
- 多租户
- 分布式/集群部署（单机单服务）

## 2. 技术选型

| 类别 | 选型 | 说明 |
|------|------|------|
| 语言 | Go 1.22+ | 单二进制部署 |
| Web 框架 | Gin | 生态成熟、中间件丰富 |
| ORM / DB 访问 | GORM + database/sql | 系统自身库用 GORM；**业务数据源用原生 database/sql 直连** |
| 系统自身存储 | **SQLite（默认，纯 Go 嵌入，单文件随服务部署）**/ MySQL（可选） | 元数据、用户、报表配置、导出任务存系统库；SQLite 开启 WAL 模式 |
| 多数据库驱动 | go-sql-driver/mysql、lib/pq、**godror（Oracle）**、microsoft/go-mssql、**modernc.org/sqlite（纯 Go）** | SQLite 选纯 Go 实现，使 godror 成为全项目唯一 CGO 依赖，降低双平台构建难度 |
| Excel 导出 | excelize（StreamWriter 流式写） | CSV 用标准库 + bufio |
| 前端 | Vue 3 + Element Plus + Vite | 构建产物由 Go 服务静态托管，单二进制交付 |
| 缓存 | 内存缓存（本期） | 元数据缓存；预留 Redis 接口 |
| 认证 | JWT（独立用户体系） | 密码 bcrypt 存储；报表支持公开访问令牌 |

### 2.1 Oracle 支持专项说明（已确认：12c 起步，支持多版本）

- 当前生产版本为 **Oracle 12c**；驱动层按"多版本兼容"设计，不同版本实例可同时接入
- 驱动采用 **godror**（官方推荐），底层 ODPI-C 遵循 Oracle Client-Server 互操作矩阵：使用 **19c/21c Instant Client** 可连接 11.2 ~ 19c 服务端，未来服务端升级 19c 无需更换驱动
- **版本自动探测与方言适配**：每个数据源连接时读取 `v$version` 探测版本
  - 12c+ → `OFFSET ? ROWS FETCH NEXT ? ROWS ONLY` 分页
  - 11g 及以下 → 自动降级 `ROWNUM` 三层嵌套分页
  - 探测结果随连接池缓存，报表配置无感知
- 部署要求：
  - 需安装 Oracle Instant Client（Basic + SDK 包），Windows 设置 `PATH`，Linux 设置 `LD_LIBRARY_PATH`
  - **唯一 CGO 依赖**：Windows 构建需 MinGW-w64 工具链，Linux 需 gcc；CI 上分平台构建，Docker（Linux）镜像内预装 Instant Client
  - Docker 镜像内预装 Instant Client，规避环境问题
- 占位符：Oracle 原生 `:name` 命名参数，与本项目约定的 `:param` 天然一致，转换层直通处理
- 元数据扫描：走 `all_tables` / `all_tab_columns` / `all_col_comments`（限定当前 schema）

## 3. 系统总体架构

```
┌─────────────────────────────────────────────┐
│              前端 (Vue 3 + Element Plus)     │
│  报表查看页 │ 报表配置页 │ 数据源管理 │ 系统管理 │
└──────────────────┬──────────────────────────┘
                   │ REST API (JSON + JWT / 公开令牌)
┌──────────────────▼──────────────────────────┐
│           Go 后端服务（单机单服务）            │
│  ┌─────────┐ ┌─────────┐ ┌───────────────┐  │
│  │ 认证授权 │ │ 报表引擎 │ │ 元数据服务     │  │
│  │ JWT+令牌 │ └────┬────┘ └───────┬───────┘  │
│  └─────────┘      │              │          │
│  ┌─────────┐ ┌────▼──────────────▼───────┐  │
│  │导出服务  │ │ 查询执行器 + 连接池管理     │  │
│  │流式/异步 │ └───────────────────────────┘  │
│  └────┬────┘  ┌─────────────────────────┐   │
│       │       │ 异步任务 Worker(goroutine)│   │
│  ┌────▼────┐  └─────────────────────────┘   │
│  │文件存储  │        │ 系统库(GORM)           │
│  └─────────┘        ▼                       │
└──────────────────────────┼──────────────────┘
                          ▼                     ▼
      导出文件目录(本地磁盘)      系统库(MySQL/SQLite)
      业务数据源(MySQL/Oracle/PG/SQLServer/SQLite...)
```

核心分层：

1. **数据源层**：多数据库连接管理，驱动可插拔（含 godror/Oracle）
2. **元数据层**：表结构、字段扫描，供 SQL 编写与条件配置使用
3. **报表引擎**：解析配置 → 绑定参数 → 执行 SQL → 结构化结果
4. **导出服务**：同步小导出（流式直写响应）+ 异步大导出（后台任务 + 文件下载）
5. **展示层**：通用列表组件，按配置渲染

## 4. 功能需求详述

### 4.1 数据源管理（需求 1）

**FR-01 数据源 CRUD**

- 字段：名称、类型（mysql/postgresql/oracle/sqlserver/sqlite）、主机、端口、服务名/SID（Oracle）、库名、用户名、密码（AES 加密存储，接口返回脱敏）、连接参数
- Oracle 额外支持连接描述符直连模式（完整 TNS 连接串），兼容 RAC/scan 等场景

**FR-02 连接测试**

- 一键测试连通性，返回耗时与数据库版本（Oracle 额外显示 `v$version` 版本号，用于分页方言探测）

**FR-03 多实例支持**

- 任意数量数据源实例，报表配置时选择所属数据源

**FR-04 连接池管理**

- 每数据源独立连接池，可配置 MaxOpenConns / MaxIdleConns / ConnMaxLifetime
- Oracle 需额外注意会话数限制，连接池默认值保守（如 Max 20），防止占满数据库进程数

### 4.2 元数据扫描（需求 3）

**FR-05 表清单扫描**：选择数据源 → 表/视图清单（表名、注释），关键字搜索

**FR-06 字段扫描**：字段名、类型、可空、默认值、主键、注释；点击复制字段名辅助写 SQL

**FR-07 元数据缓存**：缓存默认 10 分钟，支持手动刷新；各驱动适配器封装差异（`information_schema` / Oracle `all_*` 视图 / SQL Server `sys.*`）

### 4.3 报表配置（需求 2、4、5）

**FR-08 基于 SQL 创建报表**

- 报表名称、分组、数据源、SQL 编辑器（语法高亮、字段名提示、试跑校验）
- SQL 使用命名参数占位符 `:param`，引擎统一绑定参数

**FR-09 查询条件配置（核心）**

| 配置项 | 说明 |
|--------|------|
| 参数名 | 与 SQL 中 `:param` 对应 |
| 显示名 | 页面中文标签 |
| 控件类型 | 文本 / 数字 / 下拉单选 / 下拉多选 / 日期 / 日期时间 / 日期范围 |
| 匹配方式 | 等于 / 模糊 / IN / 范围 |
| 默认值 | 固定值或动态值（"今天""近7天"） |
| 是否必填 | 必填未填阻止查询 |
| 选项来源 | 固定键值对 / 指定 SQL |

**FR-10 展示列配置**：解析结果集列自动初始化；显示名、列宽、隐藏、格式化（日期/千分位/小数位）、列排序

**FR-11 基于数据库表快速建报表（需求 4）**：选表 → 自动生成基础 SQL 与查询条件草稿，再手工调整，走统一配置流程

**FR-12 报表预览与发布**：实时预览试跑；草稿 / 已发布 / 已停用 三状态

### 4.4 报表使用

**FR-13 查询列表页**

- 条件区 + 结果表格 + 分页；默认 20/50/100 条，后端分页（方言适配）
- 排序走结果列白名单校验
- **深分页优化**：当分页深度超过阈值（如 OFFSET > 10000）时，自动切换游标分页（keyset，按排序键 `WHERE key > last ORDER BY key FETCH n`），避免 Oracle/MySQL 深分页性能塌陷

**FR-14 导出（核心，已确认百万级场景）**

导出按结果量分级处理：

| 档位 | 判定 | 处理方式 |
|------|------|---------|
| 小量 | 预估 ≤ 1 万行 | 同步流式导出：`sql.Rows` 逐批读取（fetch 分批，如每批 1000 行），CSV/xlsx 流式写 HTTP 响应，内存占用恒定 |
| 大量 | 预估 > 1 万行或含慢查询标记 | **异步导出任务**：提交任务 → 后台 Worker 执行 → 完成后在"导出中心"下载文件 |

异步导出关键设计：

1. **任务化**：导出任务表（状态：排队/执行中/完成/失败，含进度百分比、文件路径、创建人、耗时）；Worker 数量可配置（默认 2），并发上限保护数据库
2. **导出格式**：**默认 Excel(xlsx)，用户可在导出时切换 CSV**；大文件场景给出提示（xlsx 单文件上限 1,048,576 行，超过自动拆分为多 Sheet/多文件，CSV 无此限制）
3. **流式落盘**：xlsx 用 excelize StreamWriter 流式写；CSV 用 bufio 流式写，不在内存中攒全量数据，百万行内存占用控制在百 MB 以内
3. **进度反馈**：每 N 万行更新一次任务进度，前端轮询展示
4. **分片查询**：对超慢 SQL，可选按主键/排序键范围分片执行（如按 ID 每片 10 万行循环查询拼接），每片独立释放游标，避免单条游标长时间占用数据库
5. **行数上限**：单任务硬上限（默认 500 万行，可配），达到即截断并标注
6. **文件管理**：导出文件本地磁盘存储，自动过期清理（默认 7 天）；下载鉴权（仅创建人/管理员，公开报表匿名下载带一次性签名链接）
7. **预估机制**：导出前先执行 `COUNT` 或驱动估算（Oracle: `num_rows` from `all_tables`），超过阈值提示走异步

**FR-15 慢查询治理（新增，针对"SQL 复杂导致查询缓慢"）**

| 手段 | 说明 |
|------|------|
| 查询超时 | 每报表可配超时（默认 30s），`context.WithTimeout` + `Rows.Close()`，超时自动取消（向数据库发送 cancel） |
| 行数上限 | 页面查询强制 LIMIT 保护 |
| 异步隔离 | 慢导出走后台任务，不阻塞页面查询与 Web 服务 |
| 只读保障 | 拦截非 SELECT；建议数据源用只读账号（双重防护） |
| 慢查询日志 | 记录执行超阈值（可配，默认 5s）的 SQL 及耗时，便于后续优化 |
| 索引提示（尽力） | 元数据服务可查看表的索引清单，辅助管理员优化 SQL |

### 4.5 系统管理

**FR-16 用户与认证（独立体系，已确认）**

- 独立用户名密码登录，JWT 签发（access + refresh），密码 bcrypt
- 权限模型：用户 → 角色（可多选，权限取并集）→ 菜单/按钮权限点（可配置）
- 内置角色：管理员（隐式 `*` 全量权限）、普通用户（仅查看已授权报表）；其余角色由管理员自建
- 菜单与按钮权限点均在「菜单管理」维护（M 目录 / C 页面 / F 按钮），角色在「角色管理」中勾选
- 接口按权限点鉴权（`RequirePerm`），前端按 `can('x:y:z')` 控制按钮显隐；角色调整后无需重新登录
- 登录失败锁定（可配，如 5 次锁 10 分钟）；最后一个管理员不可删除/停用/摘角色

**FR-17 报表公开访问（新增，已确认）**

- 报表可开启"**无需登录访问**"开关，系统生成公开访问链接（形如 `/r/{report_public_id}?token=...`）
- 实现方式：报表级访问令牌（随机串，可重置/停用），匿名请求凭令牌访问该报表的 query/export 接口
- 安全约束：
  - 公开报表仅暴露查询与导出能力，不暴露 SQL、数据源等配置信息
  - 公开报表受超时、行数上限、频率限制（简单 IP 限流）约束
  - 大量导出对匿名访问默认禁用（可配置放开）
  - 审计日志仍记录（用户记为 anonymous + IP）

**FR-18 报表分组与权限**

- 报表按分组组织；登录用户按角色可见；公开报表对所有持有链接者可见

**FR-19 操作日志**

- 记录登录、配置变更、查询执行（数据源、SQL、耗时、用户/IP）、导出任务
- 保留期可配置，定时清理

**前端工程（Vite）说明：**

| 场景 | 命令 | 说明 |
|------|------|------|
| 开发 | `cd frontend && npm install && npm run dev` | Vite 开发服务器（默认 5173，`/api` 代理到 18080），支持 HMR |

开发期访问 `http://localhost:5173/login`；生产环境为 `http://<host>:18080/login`。
地址是「干净 URL」：不带 `/ui` 前缀、不带 `.html` 后缀。服务端只认一个宿主页：
无扩展名路径一律回落到 `dist/index.html`（前端路由接管），`/assets/*` 按扩展名取静态文件，
旧的 `/ui/xxx.html` 一律 301 到新地址（兼容老书签）。

**框架与页面的分界（新增页面时照此办理）：**

| 层 | 位置 | 职责 |
|----|------|------|
| 框架 | `src/layout/AppLayout.vue` | 左侧菜单、折叠按钮、页面标题、用户菜单、内容容器 |
| 菜单 | `src/layout/SideNav.vue` | 由 `/api/auth/me` 的 `menus` 渲染，两级、可折叠 |
| 路由 | `src/router/index.js` | 路径与页面映射、标题、`meta.perm` 静态权限、`meta.activeMenu` 高亮 |
| 页面 | `src/pages/Xxx.vue` | 只写内容区（表格/表单/弹窗），不写导航、不写外层框架 |

新增一个页面 = 新建 `src/pages/Xxx.vue` + 在 `src/router/index.js` 加一条路由
（需要出现在左侧菜单里，再到「菜单管理」加一条 C 类型菜单，`path` 与路由一致）。
服务端无需改动。
模板在构建期编译，运行时不带 Vue 模板编译器。

**数据表格的两种形态：**

| 形态 | 用法 | 滚动行为 |
|------|------|----------|
| 撑满型（推荐用于列表/数据页） | 根节点 `class="rs-page-fill"`，内容容器 `class="page-body"`，表格外包 `<div class="table-wrap" ref="tableWrap">`，`el-table :height="tableHeight"`，并混入 `src/lib/tableFill.js` | 页面本身不滚，表头与分页固定，数据在表格内部滚动 |
| 自适应型 | 直接放 `el-table`，不设 `height` | 表格随行数变高，整页滚动（适合弹窗、短表） |

`tableFill` 用 `ResizeObserver` 监听包裹层，侧栏折叠、搜索区展开/收起、窗口缩放都会自动重算高度。
表格单元格与表头统一单行显示（`style.css` 里对 `.el-table .cell` 设 `white-space: nowrap`），
长文本省略，`show-overflow-tooltip` 负责悬浮显示全文。

**Driver 适配层接口（多数据库核心）：**

```go
type Driver interface {
    Open(cfg DataSourceConfig) (*sql.DB, error)
    ListTables(db *sql.DB, schema string) ([]TableMeta, error)
    ListColumns(db *sql.DB, table string) ([]ColumnMeta, error)
    ListIndexes(db *sql.DB, table string) ([]IndexMeta, error)
    QuoteIdentifier(name string) string
    Paginate(sql string, offset, limit int) string            // 含 Oracle ROWNUM/FETCH 方言
    KeysetPage(sql, keyCol string, lastKey any, limit int) string // 游标分页
    PlaceholderRebind(sql string) string                      // :param → 各库占位符
    EstimateRows(db *sql.DB, sql string) (int64, error)       // 导出量预估
}
```

## 9. 已决策项与遗留风险

### 已决策（评审全部确认，v0.3 冻结）

| # | 事项 | 决策 |
|---|------|------|
| 1 | Oracle 支持 | **必须支持**，godror + Instant Client；**12c 起步、多版本兼容**（版本探测 + 方言自动适配，可同时接入不同版本实例） |
| 2 | 认证 | 独立用户体系；报表可配置公开访问（令牌机制） |
| 3 | 百万级导出 | 同步流式 + 异步任务双模式；慢查询治理见 FR-15 |
| 4 | 部署 | 单机单服务（前端嵌入二进制）；**Windows 与 Linux 双平台均可部署**，预留 Dockerfile |
| 5 | 导出格式 | **默认 Excel(xlsx)，支持切换 CSV**；超 104 万行自动拆分 |
| 6 | 系统库 | **SQLite（纯 Go 嵌入，单文件，WAL 模式）**；MySQL 保留为可选配置 |

### 遗留风险

| # | 风险 | 说明 |
|---|------|------|
| 1 | 双平台 CGO 构建 | Windows 构建需 MinGW-w64 + Instant Client（含 x64 头文件），交付时提供各平台构建脚本与依赖清单 |
| 2 | 异步导出磁盘容量 | 百万行 xlsx 单文件可达 1~2GB（CSV 较小），默认 7 天自动清理；需确认磁盘可用空间 |
| 3 | 公开报表安全性 | 公开链接若外泄即数据暴露，公开报表默认禁用导出 + IP 限流（可配置放开） |

## 10. 验收标准（摘要）

- 支持 MySQL、**Oracle**、PostgreSQL、SQL Server、SQLite 五类数据源全流程（扫描/查询/导出）
- 新增报表全程配置化，无需改代码或重启服务
- 百万行导出：走异步任务，内存可控、有进度反馈、文件可下载且自动清理
- 慢 SQL 查询超时自动取消，不影响其他报表与服务可用性
- 公开访问报表无登录可查询，且无法获取 SQL 与数据源配置信息
- 全部查询参数占位符绑定，通过 SQL 注入用例测试；操作日志可追溯
